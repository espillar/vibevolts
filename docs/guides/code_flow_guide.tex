\section{Introduction}
This document describes the high-level architecture, module-to-module execution flow, and state
mutations within the VibeVolts space environment simulation toolkit. The simulation is structured as
a discrete event model centered around a unified state container called \texttt{sim\_data}
(instantiated as a \texttt{SimulationState} object).

\section{System Architecture \& Module Roles}
VibeVolts is structured around modular components that initialize, propagate, schedule, scan, and
process data. The key modules and their roles are:

\begin{itemize}
    \item \textbf{\texttt{minimalsimulation.py}}: Defines \texttt{SimulationState},
    \texttt{ComponentState} (with \texttt{.subset()}, \texttt{.append()}, and declarative
    \texttt{\_DEFAULTS}), live \texttt{CountsState}, and
    \texttt{SimulationState.iter\_detector\_components()} over \texttt{DotDict}.
    \item \textbf{\texttt{propagation.py}}: Loads orbital elements from TLE file paths or raw
    multi-line TLE strings and propagates satellite coordinates.
    \item \textbf{\texttt{observatories.py}}: Initializes ground-based stations
    (\texttt{add\_observatories()}) and computes their GCRS coordinates as the Earth rotates
    (\texttt{propagate\_observatories()}).
    \item \textbf{\texttt{celestialbodies.py}}: Resolves Sun and Moon coordinates via ephemerides.
    \item \textbf{\texttt{targets.py}}: Generates target coordinates on a log-radial Fibonacci
    sphere.
    \item \textbf{\texttt{cadenceController.py}}: Advances simulation time and schedules scans
    according to detector integration-time groups.
    \item \textbf{\texttt{pointing.py}}: Manages pointing spheres and updates sensor orientations,
    skipping excluded angles.
    \item \textbf{\texttt{exclusion.py}}: Provides \texttt{compute\_exclusions()} and
    \texttt{check\_sim\_exclusions()} for Sun, Moon, Earth-limb, and horizon obstruction.
    \item \textbf{\texttt{scandetectors.py}}: Matches line-of-sight geometry, applies Earth-only
    occlusion filtering, and computes radiometric signal, noise, and SNR.
    \item \textbf{\texttt{dataHandling.py}}: Accumulates detection logs into DataFrames for export
    and gap-time analysis.
\end{itemize}

\section{Execution Flow}
Simulation execution has three phases: Initialization, Configuration, and the Update/Scan Loop.

\subsection{Phase 1: Initialization}
\begin{enumerate}
    \item \texttt{create\_empty\_simulation(start\_time, delta\_time)} creates
    \texttt{SimulationState}.
    \item Initialized fields:
    \begin{itemize}
        \item \texttt{sim\_data.start\_time}, \texttt{sim\_data.time} $\rightarrow$
        \texttt{datetime} (UTC).
        \item \texttt{sim\_data.counts} $\rightarrow$ live \texttt{CountsState} dynamically
        querying component lengths (\texttt{len(sim\_data.satellites)},
        \texttt{len(sim\_data.observatories)}, \texttt{len(sim\_data.fixedpoints)}).
        \item \texttt{sim\_data.pointing\_spheres} $\rightarrow$ empty \texttt{dict}.
    \end{itemize}
\end{enumerate}

\subsection{Phase 2: Configuration}
In this phase, assets, detectors, and targets are added to \texttt{sim\_data}:
\begin{enumerate}
    \item \textbf{Satellites \& Observatories:} \texttt{add\_satellites\_from\_tle()} (from a
    file path or TLE string) and \texttt{add\_observatories()} populate
    \texttt{sim\_data.satellites} (\texttt{SatellitesState}) and
    \texttt{sim\_data.observatories} (\texttt{ObservatoriesState}), each carrying its own
    embedded \texttt{detector} (\texttt{DetectorArray}).
    \item \textbf{Detectors:} Sensors are configured via \texttt{makeDetector()} and assigned to
    \texttt{sim\_data.satellites.detector} or \texttt{sim\_data.observatories.detector}.
    \texttt{sim\_data.detector} (\texttt{get\_all\_detectors()}) and
    \texttt{sim\_data.iter\_detector\_components()} aggregate across components automatically.
    \item \textbf{Targets:} \texttt{add\_fixed\_points()} calls
    \texttt{generate\_log\_spherical\_points()} to populate \texttt{sim\_data.fixedpoints}.
    \item \textbf{Celestial Bodies:} \texttt{add\_celestial\_bodies()} allocates
    \texttt{CelestialState} for Sun and Moon positions.
\end{enumerate}

\subsection{Phase 3: Update and Scan Loop}
Once configured, the simulation loop is driven by the cadence controller:
\begin{enumerate}
    \item \texttt{initCadence()} groups detectors by unique integration times into
    \texttt{CadenceGroup} entries, setting initial \texttt{scanNext} times to
    \texttt{sim\_data.time}.
    \item Each call to \texttt{nextIntegration()} executes:
    \begin{itemize}
        \item \textbf{Time Update:} Advances \texttt{sim\_data.time = cadence.nextTime}.
        \item \textbf{Asset \& Body Propagation:} Calls \texttt{propagate\_satellites()},
        \texttt{celestial\_update()}, and \texttt{propagate\_observatories()}.
        \item \textbf{Sensor Pointing:} \texttt{update\_detector\_pointing()} iterates via
        \texttt{sim\_data.iter\_detector\_components()}, querying \texttt{exclusion()} to skip
        obscured directions.
        \item \textbf{Observation Scan:} \texttt{scandetectors()} subsets detectors via
        \texttt{det.subset(mask)}, checks FOV cones, filters Earth-limb/horizon occlusion with
        \texttt{check\_sim\_exclusions(..., earth\_only=True, use\_arcsin=True)}, and computes
        \texttt{signal}, \texttt{noise}, and \texttt{snr} on \texttt{hits = det.subset(...)}.
        \item \textbf{Rescheduling \& Collection:} Advances \texttt{group.scanNext} by
        \texttt{scanInterval}, updates the next group, and passes results to \texttt{DataHandler}.
    \end{itemize}
\end{enumerate}
